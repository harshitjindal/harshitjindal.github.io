Introduction to Open Source Software

Open Source Software is used to refer to software that is freely available for use, modification and redistribution. This makes it an attractive option for personal as well as commercial use. Most paid software today has some or the other open source alternative, with the motivation of contributing to the community good. For example, Adobe Photoshop, a paid software, has an alternative Gimp which is free and open source. Similarly, MS Office has Libre Office.

Amongst the many advantages of open source software, a few of the most prominent ones are that it encourages collaboration, promotes transparency, reduces cost due to it being free, and giving the users the flexibility to use it however they require. Contributions to open source software is also widely recognized as giving back to the community, in fact, some big-tech organizations even promote open source software by running programs like the prestigious Google Summer of Code. Many developers also see it as an opportunity to highlight their work, and to learn tech stacks by contribution to a real life projects with real users and tangible impacts.

The Kubernetes Project

Introduction and History of the Movement


The Kubernetes Logo

Also known as K8s, Kubernetes is an open source system for managing containerized applications across multiple hosts. It provides basic mechanisms for the deployment, maintenance, and scaling of applications. 1

The now widely popular Kubernetes project was developed by Google based on their experience with an internal tool for container orchestration called Borg. While Borg was working fine for their own usecase, it had massive resource requirements, something which not everyone had. This led to Google to create Kubernetes, with the following design-factors coming directly from their learnings with Borg: 2

  1. Pods:

    • It is the core scheduling unit in Kubernetes.
    • It allows several containers to be grouped together, which enables collective scheduling.

  2. Services:

    • Kubernetes supports naming and load balancing through services.
    • Service abstraction can be mapped to a dynamic set of pods via label selectors.

  3. Labels:

    • Kubernetes uses labels to provide flexibility in managing the services or subsets of tasks within a collection.
    • It is extremely useful for scenarios which require uniform management of related service instances.

  4. IP-per-Pod:

    • In Borg, tasks on a machine share the host’s IP address, which imposes a burden on the infrastructure and app developers.
    • Kubernetes assigns an IP at the POD level to address this challenge.

Development of Kubernetes also allowed Google to provide a tool like Borg to best serve the needs of Google Cloud customers. Kubernetes was later open-sourced in 2014, and is now maintained by the Cloud Native Computing Foundation (CNCF).

Features of Kubernetes

With it being open source, and with the powerful backing of Google and CNCF, Kubernetes has become an extremely feature-rich and mature container orchestrator, with the following being some of it’s most notable features: 3

  1. Automated Rollouts and Rollbacks:

    • Kubernetes smoothly updates your app and monitors its health.
    • Rollbacks occur if issues arise, ensuring stability.
    • Benefit from a growing range of deployment solutions in the ecosystem.

  2. Service Discovery and Load Balancing:

    • Kubernetes assigns IPs and DNS names to Pods for easy service discovery.
    • Enables seamless load balancing across Pods.

  3. Storage Orchestration:

    • Automatically mounts storage from various sources like local, cloud, or network systems.

  4. Self-Healing:

    • Restarts, replaces, and reschedules containers as needed.
    • Ensures containers are ready before advertising to clients.

  5. Secret and Configuration Management:

    • Deploy and update secrets and configurations without rebuilding images.
    • Maintains security by not exposing secrets in stack configurations.

  6. Automatic Bin Packing:

    • Places containers based on resource requirements without sacrificing availability.
    • Optimizes resource utilization by mixing critical and best-effort workloads.

  7. Batch Execution:

    • Manages batch and CI workloads, replacing failing containers if necessary.

  8. Horizontal Scaling:

    • Easily scale applications up or down via commands, UI, or automatically based on the demand.

  9. IPv4/IPv6 Dual-Stack:

    • Allocates both IPv4 and IPv6 addresses to Pods and Services so the user has the choice to use whichever is more suitable.

  10. Designed for Extensibility:

    • Enhance Kubernetes cluster features without altering upstream source code.

Components of Kubernetes

All of the goodness of Kubernetes is made possible by its underlying components, which are depicted below:

Image source: Offical Kubernetes Documentation

Any functional deployment of Kubernetes is in the form of a cluster, each of which has one or more worker machines called worker nodes. These nodes are what contain the “containerized applications”, for example using Docker images. The primary purpose of these worker nodes is to host the application in what’s called a pod (discussed in detail later).

There is a control plane that manages the worker nodes and the Pods in the cluster. In production environments, the control plane usually runs across multiple computers and a cluster usually runs multiple nodes, providing fault-tolerance and high availability. 4

This control place also has an API server whose primary purpose is to expose the Kubernetes API which serves as the frontend to interact with the control plane.

To summarize, a Kubernetes deployment is called a Kubernetes cluster, and can be thought of as the following major parts:

  1. Control plane: Manages the worker nodes and pods in the cluster.
  2. Worker Node(s): A cluster will have at least one worker node, and each node is responsible for hosting the containerized application in pods.
  3. API Server: A component of the conrol plane which exposes the Kubernetes API.

Now that the prerequisites are discussed, the components of a Kubernetes cluster are:

  • Control Plane Components:

    • kube-apiserver
      • The Kubernetes API server.
      • Front-end to the cluster’s shared state.
    • etcd
      • Distributed key-value store that stores configuration data for the cluster.
      • Ensures consistent and reliable cluster state.
    • kube-scheduler
      • Assigns nodes to newly created pods.
      • Considers resource requirements and constraints.
      • Supports multiple scheduling algorithms.
    • kube-controller-manager
      • Manages controllers that regulate the state of the cluster.
      • Examples include replication controller and endpoint controller.
    • cloud-controller-manager
      • Extends the cluster with cloud provider-specific control logic.
      • Allows cloud providers to interact with the cluster.

  • Worker Node Components:

    • kubelet
      • Node agent that ensures containers are running on a node.
      • Manages pods and their containers.
      • Communicates with the API server.
    • kube-proxy
      • Maintains network rules on nodes.
      • Enables communication across the cluster.
      • Implements Kubernetes service concepts.
    • Container runtime
      • Software responsible for running containers.
      • Examples include Docker, containerd, and CRI-O.
      • Handles container lifecycle, image deployment, and resource isolation.

A few components that warrant delving in more detail are listed below:

1. Kubernetes API (kube-apiserver)

  • Definition: The control plane component that exposes the Kubernetes API.
  • Functionality:
    • Allows users and controllers to communicate with the cluster.
    • Serves as the entry point for all operations in the cluster.
  • Key Features:
    • Validates and processes RESTful requests.
    • Serves as the hub for communication between other components.
    • Authenticates and authorizes incoming requests.

2. Kubernetes Objects

  • Definition: Entities representing the state of the cluster.
  • Examples:
    • Pods, Services, Replication Controllers.
  • Functionality:
    • Described in YAML or JSON files.
    • Defines the desired state and characteristics of applications.
  • Significance:
    • Managed and maintained by the Kubernetes API.
    • Changes to objects trigger the desired state in the cluster.

3. Pods

  • Definition: The smallest deployable units in Kubernetes.
  • Composition:
    • Can contain one or more containers that share the same network namespace.
    • Containers in the same pod are scheduled together on the same machine.
  • Use Cases:
    • Support co-located and co-operating processes.
    • Facilitate communication and shared state between containers.
  • Management:
    • Managed by the Kubernetes API.
    • Can be scaled horizontally to meet application requirements.
